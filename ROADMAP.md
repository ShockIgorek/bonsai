## 8. Приоритеты 2.0 (новые переменные)

Цель: кроме важности учитывать время выполнения и сложность задачи, а для каждого настроения — свои направления и веса критериев.

**Правило продукта:** объективная оценка (замеры таймера/фактическое время) имеет больший вес, чем субъективная (оценка при создании или тест).

- [x] **Глобальные поля задачи:** `difficulty`, `timeScore` + дефолты для старых задач
- [x] **Создание:** примерное время в минутах → `timeScore` 0–10; сложность задаётся при создании
- [x] **Тиндер:** убраны `+/-`; три значения: время словами — важность — сложность
- [x] **Время:** субъективная оценка через тест + объективные замеры (таймер/ручной ввод), объективное важнее
- [x] **Фактическое время:** таймер/ручной ввод, среднее последних 10 перекрывает субъективную оценку
- [x] **Сложность:** среднее последних 10 оценок; источники — создание, выполнение, тест; при выполнении можно пропустить
- [x] **Попарный тест:** три измерения, вопрос по наименее покрытому измерению, пары с учётом веток и якорей
- [x] **Якоря:** фактические замеры не перезаписываются, пары «факт против факта» не сравниваются
- [x] **Интерполяция:** субъективные время и сложность подтягиваются к фактическим значениям, выход за диапазон прижимается к min/max
- [x] **Маркировка:** бейджи «факт», «калибровка», «оценка» в Тиндере и тесте
- [x] **Прогресс по трём измерениям:** уровни «примерная / средняя / высокая» по 1/2/3 сравнениям
- [x] **Базовая взвешенная сортировка Тиндера:** важность + скорость + сложность с дефолтными весами `0.6 / 0.25 / 0.15`
- [x] **Карточка настроения:** влияние критериев и топ-3 приоритетных веток/задач
- [ ] **Веса настроения:** 3 вопроса о направлениях (важные/неважные, короткие/длинные, лёгкие/сложные) + попарный тест критериев
- [x] **Веса и направления по настроениям:** `mood.sorting`, экран настройки, ручные веса и направления
- [x] **Профиль настроения:** пресеты «Баланс» / «Отдых» / «Я машина»
- [ ] **Калибровка весов парами:** online-логистическая регрессия, сначала общие веса, потом по настроениям
- [x] **Таймер выполнения** и история фактического времени
- [x] **Карточка:** время в нормальных единицах (ч/мин/сек), 0–10 только для сортировки

## 12. Идеи на будущее

- [ ] **Обучение на фактических выполнениях:** выполнения и пропуски должны влиять на приоритет/релевантность, а не на веса сортировки. Если свайпнули задачу и выполнили следующую, она была важнее или удобнее. Для прогноза нужны события показов и свайпов, дни недели, время суток, циклы и история. Данных для обучения пока мало — вернуться после накопления статистики.
- [ ] **Адаптивные веса через явную калибровку:** online-логистическая регрессия на парах задач, сначала общие веса, потом отдельные поправки по настроениям.
- [ ] **Опциональная привязка времени/сложности к настроению:** чекбокс в задаче, если глобальных значений когда-нибудь станет недостаточно.
- [ ] **Рутины и цепочки:** последовательности задач («утренняя рутина», «вечерний ритуал»). Пока идея, без внедрения.

## 13. Решения из обсуждения (ноябрь 2026)

### Повторяемость, время и дедлайны

- [ ] **Календарная повторяемость:** дни недели, сменный график (например, 1 рабочий / 2 отдыха), «3 раза в неделю», время суток. Не только интервал от выполнения.
- [ ] **Дедлайны в Тиндере:** обратный отсчёт, визуальное выделение, повышение приоритета просроченным.
- [ ] **Нелинейная срочность:** приоритет растёт по мере приближения к дедлайну с учётом даты создания; не просто «дедлайн завтра = +1».
- [ ] **Уведомления о дедлайнах:** после внедрения мобильного приложения и push.
- [ ] **Адаптивные интервалы:** предлагать пересмотр интервала циклической задачи, если она регулярно выполняется досрочно или с опозданием. Не менять автоматически.
- [ ] **Отложить:** рассмотреть позже без новой постоянной кнопки — long-press на «скрыть», жест или второй уровень действия. Сейчас не внедрять.

### Папки, поиск и статистика

- [ ] **Завершение папки:** когда все дети закрыты, уведомить и спросить: удалить папку или оставить её как задачу.
- [ ] **Разбиение задач:** после повторных пропусков или высокой сложности мягко предлагать разбить задачу на подзадачи. Без чувства вины и с кнопкой «не сейчас».
- [ ] **Третий экран/таб-бар:** поиск по задачам и архиву, фильтры по времени, типу, ветке и статусу. Следующий крупный шаг после тестового бэкапа.
- [ ] **Фильтр по доступному времени:** 5 / 15 / 30 / 60 минут в Тиндере. Без новой сущности задачи — временный фильтр интерфейса.
- [ ] **Экран статистики:** отдельный экран с итогами, сериями и временем. На ПК и планшете — расширенная аналитика.
- [ ] **Ежедневный дайджест/фокус:** «3 главных на сегодня», вечерние итоги. После статистики.

### Настроения и видимость задач

- [ ] **Видимость по веткам:** настроение хранит include/exclude для веток. Новые задачи автоматически наследуют видимость ветки, их не нужно скрывать по одной.
- [ ] **Наследование настроений:** при создании настроения брать фильтры, приоритеты и веса из похожего настроения.
- [ ] **Принцип «без вины»:** обычный свайп остаётся нейтральным; не спрашивать причину каждый раз; подсказки только после повторных пропусков и с кнопкой «не сейчас».
- [ ] **Настройки интерфейса в бургере:** включать/выключать блоки, подсказки, уровень детализации и дополнительные панели.
- [ ] **«Почему эта карточка выше»:** необязательная панель/экран с факторами сортировки: важность, скорость, сложность, кулдаун, дедлайн. Не в основном интерфейсе, а в настройках или по запросу.

## 14. Принципы продукта

- **Не плодить сущности без необходимости.** Сначала используем дерево, настроения и существующие жесты.
- **Дефолты должны работать без настройки.** Калибровка, веса и фильтры — опциональны.
- **Пользователь понимает, почему карточка здесь.** Сложность можно скрывать в настройках, но объяснение должно быть доступно.
- **Без чувства вины.** Пропуск задачи — нормальная ситуация; приложение не должно стыдить.
- **Настройки интерфейса — в бургере.** Главный экран остаётся простым.
- **Сначала данные и мобильность, потом сложная аналитика.** Хрупкое localStorage-хранилище важнее новых красивых экранов.
- **Одна фича — один проверяемый сценарий.** После каждой механики обновляем тесты, бэкап и чек-лист.
